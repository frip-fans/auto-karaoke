# 服务器实测记录（仅保留统计）

实验环境：Linux aarch64，4 个逻辑 CPU，23.41 GiB RAM，没有计算 GPU；Python 3.12.3。分离和语音阶段分别在独立进程运行。以下为先前真实 30 秒歌曲片段的测量，源文件、分轨、日志、歌词与截图不随仓库保存。

| 阶段 | 30 秒片段耗时 | 进程峰值 RSS | 说明 |
| --- | ---: | ---: | --- |
| MDX `UVR-MDX-NET-Inst_HQ_3.onnx` | 50.68 秒 | 2.52 GiB | 分离含预处理与文件写入；另有约 1.59 秒加载 |
| MelBand RoFormer Big Beta6x | 439.58 秒 | 4.08 GiB | FP32；约为 MDX 的 8.67 倍时间 |
| faster-whisper small | 16.76 秒 | 812 MiB | CPU int8；另有约 8.20 秒加载 |
| NextFire 日语 CTC 模型 | 10.75 秒 | 1,786 MiB | CPU FP32；另有约 0.74 秒加载 |
| 720p ASS 烧录 | 25.17 秒 | 未记录 | libx264；不是 GPU 编码 |

RSS 是进程常驻内存峰值，**不是显存需求**。上述时长不含首次下载；不同阶段加载统计边界略有差异，不把它们相加当作严格端到端基准。

MDX 权重文件约 66.8 MB；ONNX 浮点 initializer 元素共 16,684,228 个，此数不等同于严格的可训练参数统计。Big Beta6x 实际 427,044,292 参数，权重文件约 1.71 GB。NextFire 模型实际 315,471,520 参数。

Big Beta6x 使用模型 12 秒窗口、overlap=2、单窗口推理。按窗口数外推一首约 304 秒歌曲可能约 92 分钟，**没有真正跑完整首以验证这个估算**。

试听结论来自用户主观反馈：大模型仍有残留，用户更喜欢 Logic Pro 的拆分结果。因此正式伴奏保留 Logic Pro 导入方案。更大的模型并未在这次实验中证明更符合用户听感。

原样片已验证日语 + 假名 + 扫色、视频和音频完整解码、时间边界合法、换轨前后视频编码数据一致，以及整曲音频与片段音频的时间原点换算。画面做过抽帧检查；没有完成逐句听音验收。

整理后的合成测试验证 CTC 重复字符、无效时间轴、手工覆盖保留、字幕生成、纯音频／视频输入、片段／整曲伴奏换轨，以及视频流不重新编码。合成测试不评估分离音质或歌词识别准确率。
